# Регистрация школы (issue #6)

Перед запуском API применить миграции, включая `000002_school_accounts`.

`POST /api/v1/schools/register`

```json
{"login":"school","email":"school@example.com","password":"password123"}
```

Ответ `201`:

```json
{"school_id":"uuid","login":"school","email":"school@example.com"}
```

Логин обязателен (до 50 символов), email — до 254 байт, пароль — от 8 до 1024 байт. Пробелы вокруг логина и email удаляются, email приводится к нижнему регистру. Email и логин уникальны без учёта регистра внутри таблицы. Пароль хранится как PBKDF2-HMAC-SHA256 (600000 итераций, случайная соль 16 байт, ключ 32 байта).

Ошибки имеют вид `{"error":{"code":"account_exists","message":"Email or login already registered"}}`: `400` — невалидный запрос, `409` — занятый email или логин, `500` — внутренняя ошибка без деталей БД, `503` — обработчик занят другими регистрациями; попробуйте позже.

Школа имеет много учеников; ученик принадлежит одной школе. Для каждого ученика триггер атомарно создаёт `student_info` с балансом 1000.00 (100000 минимальных денежных единиц), нулевой серией активности и пустым избранным. Профиль связан с учеником общим первичным ключом; избранное уникально по паре ученик/тикер. Самостоятельной регистрации учеников пока нет: создание учеников школой требует отдельного авторизованного сценария.

Таблицы портфеля и операций относятся к issue #14 и здесь не создаются. Справочник инструментов в текущей базе отсутствует, поэтому внешний ключ для тикера пока не задан.

Проверка:

```powershell
go test ./...
docker compose --profile test up -d --wait db-test
$env:TEST_DATABASE_URL = 'postgres://investor_test:investor_test@localhost:5433/myinvestor_test?sslmode=disable'
go test -count=1 ./internal/database
```

Интеграционный тест использует временную схему только в базе с суффиксом `_test` и проверяет up/down/up, уникальность email, внешние ключи, единственность профиля и начальные значения.
