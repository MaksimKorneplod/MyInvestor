# Руководство по внесению изменений в MyInvestor

Добро пожаловать в команду! Этот документ описывает процесс работы с кодом, чтобы мы могли эффективно сотрудничать и не сойти с ума от конфликтов в Git.

## 📋 Основные принципы

1. **Каждая задача = новая ветка = новый Pull Request (MR)**
2. **Никаких коммитов напрямую в `main` или `develop`** — только через PR
3. **Code Review обязателен** — тимлид должен аппрувить каждый PR перед мержем
4. **Связь с задачами** — каждый PR должен ссылаться на задачу в таск-трекере

---

## 🌿 Ветвление (Git Flow)

У нас используются следующие ветки:

- **`main`** — стабильный релиз (только для демо преподавателю)
- **`develop`** — текущая разработка (все фичи мержатся сюда)
- **`feature/*`** — ветки для отдельных задач (создаются от `develop`)

---

## 📝 Именование веток

Формат: `feature/username/GO-<номер-задачи>_краткое_описание`

**Примеры:**
```
feature/maksim/GO-1_add_main_screen
feature/alex/GO-5_implement_csv_parser
feature/ivan/GO-12_fix_dividend_calculation
```

**Правила:**
- Используй свое имя (или ник) вместо `username`
- Номер задачи бери из таск-трекера (GitHub Projects)
- Описание пиши на английском, через подчеркивание, кратко и понятно
- Не используй пробелы и спецсимволы

## 🔄 Процесс работы над задачей

### Шаг 1: Создай ветку от `develop`

```bash
git checkout develop
git pull origin develop
git checkout -b feature/your_name/GO-12_task_description
```

### Шаг 2: Работай, коммить, пушь

```bash
git add .
git commit -m "GO-12: add dividend calculation logic"
git push origin feature/your_name/GO-12_task_description
```

### Шаг 3: Перед созданием PR — синхронизируйся!

**ЭТО КРИТИЧНО!** Пока ты работал, в `develop` могли влить другие фичи. Перед созданием PR:

```bash
git checkout develop
git pull origin develop
git checkout feature/your_name/GO-12_task_description
git merge develop  # или git rebase develop
# Если есть конфликты — разреши их
git push origin feature/your_name/GO-12_task_description
```

### Шаг 4: Создай Pull Request

- **From:** `feature/your_name/GO-12_task_description`
- **To:** `develop` (НЕ в `main`!)

### Шаг 5: Заполни описание PR по шаблону

Используй чеклист ниже. Не пропускай пункты!

### Шаг 6: Напиши в чат команды

Скинь ссылку на PR и тегни тимлида:
> @mexkorneplod готов PR: [ссылка]

### Шаг 7: Дождись Code Review

Тимлид посмотрит код, напишет комментарии. Исправь замечания и снова попроси ревью.

### Шаг 8: Мерж

После аппрува тимлид смержит PR. Ветка автоматически удалится.

## 🔗 Зависимые задачи

**Ситуация:** Ты сделал задачу #1 и хочешь начать задачу #2, которая зависит от кода из #1.

**Решение:**
1. Создай ветку для задачи #2 **от ветки задачи #1** (не от `develop`!):
   ```bash
   git checkout feature/your_name/GO-1_first_task
   git checkout -b feature/your_name/GO-2_second_task
   ```

2. Когда создаешь PR для задачи #2, он должен смотреть **в ветку задачи #1**:
   - **From:** `feature/your_name/GO-2_second_task`
   - **To:** `feature/your_name/GO-1_first_task`

3. После того как задача #1 будет смержена в `develop`, измени base ветку PR задачи #2 на `develop`.

**Важно:** Обсуди с тимлидом такие ситуации заранее, чтобы не запутаться.

## 🎯 Где брать номера задач?

Все задачи хранятся в **GitHub Projects** (доска в репозитории).

1. Зайди в раздел **Projects** репозитория
2. Найди задачу в колонке `To Do`
3. Номер задачи — это номер Issue (например, `#12`)
4. Возьми задачу в работу: перетащи в колонку `In Progress` и назначь себя (Assignees)

## ⚠️ Частые ошибки

### 1. Забыл синхронизироваться перед PR
**Симптом:** Конфликты при мерже, старые версии файлов.
**Решение:** Всегда делай `git merge develop` перед созданием PR.

### 2. Коммит в `main` или `develop` напрямую
**Симптом:** GitHub не даст это сделать (защита веток).
**Решение:** Всегда создавай feature-ветку и делай PR.

### 3. Огромный PR на 1000+ строк
**Симптом:** Тимлид устанет ревьюить, будут пропущены баги.
**Решение:** Разбивай большие задачи на несколько мелких PR. Один PR = одна логическая задача.

### 4. Нет описания в PR
**Симптом:** Тимлид не понимает, что ты сделал, как тестировать.
**Решение:** Заполняй шаблон полностью. Это экономит время всем.

### 5. Застрял на проблеме и молчишь
**Симптом:** Задача висит днями, прогресса нет.
**Решение:** Если застрял больше чем на 1 час — пиши в чат.
